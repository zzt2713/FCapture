## 2. 目录结构

目录结构以当前源码为准。补充两条铁律：

1. **`#include <windows.h>` 只允许出现在 `src/platform/win/` 下。**
   其他模块通过 `WinUtil.h` 暴露的干净接口调用；`WinUtil.h` 里不得出现 `HWND` 等 Win32 类型，
   用 `quintptr` 或封装 ID 替代。
2. **`src/ui/` 是唯一允许引入 ElaWidgetTools 头的目录**（外加 `main.cpp` 对 `ElaApplication` 的初始化）。
   业务逻辑层（core / snip / annotate / paste / tools）不得直接依赖 Ela。

## 3. 编码规范

### 3.1 命名

| 类别 | 规则 | 示例 |
|---|---|---|
| 类名 | PascalCase | `PinWindow`、`AnnotationModel` |
| 成员变量 | `m_` + camelCase | `m_paintBarVisible` |
| 局部变量 / 函数 | camelCase | `hitTestAnchor()` |
| 信号 / 槽 | camelCase | `snipFinished`、`onToolChanged` |
| 常量 | `k` + PascalCase | `kMaxUndoDepth`、`kPenLevels` |
| 文件名 | 与主类名一致 | `PinManager.h/.cpp` |

### 3.2 Qt 惯例

- **一律新式 connect**（函数指针 / lambda），**禁止** `SIGNAL()` / `SLOT()` 宏。
- 字符串字面量用 `QStringLiteral()`。
- 对象所有权交给 Qt 父子树；无父对象才用 `std::unique_ptr`。
- 禁止裸 `new` 后不给 parent 又不 delete。
- 跨线程信号槽默认 `Qt::AutoConnection`；需要强制队列时显式写 `Qt::QueuedConnection`。

### 3.3 头文件

- 统一 `#pragma once`，不用 include guard。
- 头文件只 include 必需的；能用前置声明就不 include。
- 引号路径一律相对 `src/`（如 `#include "ui/Theme.h"`），因为 `fcapture_core` 的 `PUBLIC` include 目录是 `src`。

### 3.4 坐标系

> **这是本项目最容易出错的地方，务必读懂。**

| 坐标类型 | 定义 | 出现位置 |
|---|---|---|
| **逻辑坐标** | Qt 的 `QWidget::pos()` / `globalPos()` 坐标系，受 DPI 缩放影响 | 全部 UI 交互、选区、标注模型 |
| **物理像素** | 图像数据真实像素 | `QImage` / 截图快照 `QPixmap` |
| **快照坐标** | `逻辑坐标 - virtualGeometry.topLeft()`，再按 dpr 缩放 | 截图层内部绘制 |

铁律：

- **标注模型（`Annotation` 体系）一律使用逻辑像素坐标**，与选区同一坐标系，原点 = 截图层左上角。
- **只在导出时**按 `devicePixelRatio` 换算物理像素（`SnipOverlay::composeResultImage()`）。
- 多屏不同 DPI 时，`ScreenCapturer` 用 `max(dpr)` 统一采样；绘制时按各屏自己的 dpr 定位。

### 3.5 错误处理

- 用户可见的失败必须有明确提示（托盘气泡 / Toast / 状态栏），不能静默吞掉。
- 不吞异常：`try/catch` 后至少写日志。
- Win32 API 必须检查返回值并记录 `GetLastError()`。
- 可降级的功能（元素检测、虚拟桌面、热角）失败时**静默降级**，但要写 `qWarning`。

### 3.6 禁止事项

- ❌ 留 `TODO` / 空实现占位交付
- ❌ 注释掉的死代码
- ❌ 未使用的 include / 变量 / 函数
- ❌ 三个以下调用点的代码抽成类（过度抽象）
- ❌ 引入 Qt 之外的 UI 库（Ela 是唯一例外，已批准）

## 4. Ela 接入规则

> 以下是 Ela 接入必须遵守的约束。

### 4.1 库信息（已实测）

| 项 | 值 |
|---|---|
| 版本 | 2.0.2（`ElaDef.h` 中 `ElaDefVersion`） |
| 根目录 | `D:/cppsoft/MsvcEla/` |
| 头文件 | `include/*.h`（298 个，全部平铺无子目录） |
| 导入库 | `lib/ElaWidgetTools.lib` |
| 动态库 | `lib/ElaWidgetTools.dll` 与 `bin/ElaWidgetTools.dll`（同一份，5.47 MB） |
| CMake 配置 | `lib/Cmake/ElaWidgetToolsConfig.cmake` —— **不可用** |
| 依赖 | `Qt6Core.dll` / `Qt6Gui.dll` / `Qt6Widgets.dll`（release）、`MSVCP140`、`VCRUNTIME140(_1)`、`d3d11`、`dxgi`、`dwmapi`、`SHCore`、`GDI32`、`USER32` |
| 内嵌资源 | `ElaAwesome.ttf`（图标字体，编译进 DLL，无需外部文件） |

**ABI 兼容性已核对**：`ElaWidgetTools.lib` 里的 Qt 导入符号
（Qt6Widgets 1462 个、Qt6Gui 430 个、Qt6Core 502 个）逐个比对 Qt 6.8.3 对应 DLL 的导出表，
**全部命中，零缺失**。不需要重新编译 Ela 源码，直接链 `IMPORTED` 目标即可。

### 4.2 CMake 接入（固定写法，不要改）

`find_package(ElaWidgetTools CONFIG)` **会失败**：`ElaWidgetToolsConfig.cmake` 里
`include(${PACKAGE_PREFIX_DIR}/lib/cmake/ElaWidgetToolsTargets.cmake)`，
而实际目录是 `lib/Cmake/`，且根本没有 `ElaWidgetToolsTargets.cmake` 这个文件。

正确做法是在 `CMakeLists.txt` 里手写 IMPORTED 目标：

```cmake
set(ELA_ROOT "D:/cppsoft/MsvcEla" CACHE PATH "ElaWidgetTools root")

add_library(ElaWidgetTools SHARED IMPORTED)
set_target_properties(ElaWidgetTools PROPERTIES
    IMPORTED_IMPLIB "${ELA_ROOT}/lib/ElaWidgetTools.lib"
    IMPORTED_LOCATION "${ELA_ROOT}/bin/ElaWidgetTools.dll"
    INTERFACE_INCLUDE_DIRECTORIES "${ELA_ROOT}/include"
)
target_link_libraries(fcapture_core PUBLIC Qt6::Widgets ElaWidgetTools)

# 打包时把 DLL 复制到 dist
add_custom_command(TARGET FCapture POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E copy_if_different
            "${ELA_ROOT}/bin/ElaWidgetTools.dll"
            "$<TARGET_FILE_DIR:FCapture>"
)
```

要点：

- 必须是 `SHARED IMPORTED` + `IMPORTED_IMPLIB`（Windows DLL 的导入库）+ `IMPORTED_LOCATION`（运行时 DLL）。
- `INTERFACE_INCLUDE_DIRECTORIES` 指向 `include`，因为 Ela 头文件互相之间用平铺 include（`#include "ElaDef.h"`）。
- `POST_BUILD` 复制 DLL 比依赖 `windeployqt` 更可靠（windeployqt 不认识第三方 DLL）。

### 4.3 初始化顺序（main.cpp）

```cpp
QApplication app(argc, argv);
app.setStyle(QStyleFactory::create(QStringLiteral("Fusion")));   // Ela 基于 Fusion 调教
// ...
eApp->init();                                 // ElaApplication，必须在创建任何 Ela 控件之前
eTheme->setThemeMode(ElaThemeType::Dark);     // 默认暗色，跟随项目视觉
```

- `eApp->init()` 内部安装全局事件过滤器、初始化 Mica、注册图标字体；**漏掉会白屏 / 图标全变方框**。
- 主题只允许 `ElaThemeType::Light` / `Dark`；本项目默认 `Dark`，可在首选项切换。
- **`ElaApplication` 是单例**，不要 `new`，用 `eApp` 宏。

### 4.4 视觉一致性规则

1. **不要给 Ela 控件写 QSS。** Ela 全部自绘 `paintEvent`，任何 `ElaPushButton { ... }` 之类的
   QSS 都会让 Qt 套一层 `QStyleSheetStyle`，破坏自绘结果（圆角、动画、图标全丢）。
2. **收窄全局 QSS。** `Theme::baseStyleSheet()` 只保留字体规则；配色一律走 Ela 主题，
   否则 `QWidget { color: … }` 会污染 Ela 控件文字颜色，浅色主题下出现白底白字。
   截图层自绘控件需要的样式挂在 `Theme::overlayStyleSheet()`，由 `SnipOverlay::setStyleSheet()` 单独加载。
3. **强调色统一。** 项目主色 `#3D8BFD`，通过
   `eTheme->setThemeColor(ElaThemeType::Dark, ElaThemeType::PrimaryNormal, …)` 注入，不要两套体系各写一份。
4. **图标二选一**：
   - Ela 控件内部用 `ElaIconType::IconName`（`ElaAwesome.ttf` 字形）。
   - 截图工具栏继续用 `resources/icons/*.svg`（`ToolIcons` / `IconFactory`），
     因为它们是 20×20、线宽 1.5 的定制品，换成字体图标会糊。

### 4.5 明确不用 Ela 的地方

| 模块 | 原因 |
|---|---|
| `SnipOverlay` | 全屏自绘遮罩，必须逐像素控制，不能用任何标准控件外观 |
| `PaintBar` | 自绘工具栏，尺寸/间距/图标都按 Snipaste 原版对齐 |
| `PinWindow` | 无边框透明置顶窗口，Ela 的 AppBar/圆角/阴影会毁掉它 |
| `Whiteboard` | 同上，全屏画布 |
| `TextInputBox` | 必须完全透明、字体与最终标注一致 |
| `SizeInputBox` | 截图层子控件，随选区定位 |
| 设置窗口的**外层壳** | 按项目要求**不用 `ElaWindow`**（导航栏 + Mica 主窗口壳），用 `ElaDialog` |

### 5.2 标准流程（**用 VS 生成器，不要用 Ninja**）

本机设置了 `NoDefaultCurrentDirectoryInExePath=1`，在 bash 里
`cmd //c "call vcvars64.bat && ..."` 会失败（已实测）。
VS 生成器由 CMake 自己定位 MSVC，不需要 vcvars 环境。

```bash
# 1. 配置（首次或 CMakeLists 改动后）
D:/CMake/bin/cmake -S . -B build -G "Visual Studio 17 2022" -A x64 \
  -DCMAKE_PREFIX_PATH=D:/Qt/6.8.3/msvc2022_64

# 2. 编译
D:/CMake/bin/cmake --build build --config Release

# 3. 复制 exe（VS 生成器产物在 build/Release/）
mkdir -p dist/F-Capture
cp -f build/Release/FCapture.exe dist/F-Capture/

# 4. 打包依赖
D:/Qt/6.8.3/msvc2022_64/bin/windeployqt.exe --release --no-translations \
  --no-system-d3d-compiler --no-opengl-sw dist/F-Capture/FCapture.exe

# 5. 复制 Ela DLL（若 POST_BUILD 已做，这步是双保险）
cp -f D:/cppsoft/MsvcEla/bin/ElaWidgetTools.dll dist/F-Capture/
```

一键：`./scripts/build.sh` / `./scripts/build.sh clean` / `./scripts/smoke-test.sh`

### 5.3 VS 生成器的坑

- **不要**设 `CMAKE_BUILD_TYPE`（多配置生成器用 `--config Release`）。
- 产物路径是 `build/Release/`，不是 `build/`。
- `qt_add_executable(... WIN32)` 参数照样有效，生成的是无控制台窗口。
- 增量构建有时不重跑 `AUTOMOC`；改了头文件里的 `Q_OBJECT` 后行为异常时用 `--clean-first`。

### 5.4 打包产物必须包含

```
dist/F-Capture/
├── FCapture.exe
├── ElaWidgetTools.dll          ← 迁移后新增，缺失会导致启动即崩
├── Qt6Core.dll
├── Qt6Gui.dll
├── Qt6Widgets.dll
├── Qt6Network.dll
├── Qt6Svg.dll
├── 用户手册.md
└── platforms/qwindows.dll
```

**提示音不需要额外文件**：`resources/result.mp3` 已通过 `qt_add_resources` 编进 exe，
`SoundPlayer` 首次播放时写到临时文件再交给 MCI。不要再依赖 `sounds/` 目录
（POST_BUILD 只复制到 `build/Release/`，打包时不会带进 dist，用户侧就是"没有声音"）。

### 5.5 编译失败时

自己读错误、自己修、自己重试。**连续 3 次修不好**才向用户报告，并附完整错误日志。

`eTheme->getThemeColor(...)` 取色，保证跟随主题切换。

### 6.3 菜单

菜单统一用 **`ElaMenu`**（自绘圆角 + 阴影 + hover 胶囊 + 展开动画）。
旧的 `SnipMenu` / `DarkMenuStyle` 已删除，不要重新引入。

菜单图标必须走 `AppMenu::addIconAction`（内部用 `ElaIcon` 生成矢量图标），
不要用 `QMenu::addAction(QIcon)` —— 那是位图，100% 缩放下就发虚。

两条必须遵守：

1. **不要在 QSS 里写 `QMenu` 规则** —— `QStyleSheetStyle` 会包一层，破坏 Ela 自绘。
2. **不要给 QSS 的 `QWidget` 选择器设 `background-color`** —— `QMenu` 也是 `QWidget`，
   会被刷上不透明底色，`WA_TranslucentBackground` 失效，圆角变直角、阴影被填满。

### 6.4 截图交互行为（已定型，改前先读）

| 行为 | 约定 |
|---|---|
| 默认模式 | 进截图直接是**元素检测**（Snipaste 手感：指哪块框哪块）。`Tab` 循环 元素 → 窗口 → 自由 |
| UIA 取元素 | **必须传遮罩下方真实窗口的 HWND**（`WindowDetector::windowFromPoint`），由 `IUIAutomation::ElementFromHandle` 取根节点后再按光标向下找最深子元素。直接用 `ElementFromPoint` 会命中我们自己的全屏遮罩，结果永远是"整屏" —— 这是元素检测看起来完全失灵的根因 |
| 悬停检测（未选区） | 把检测到的窗口/元素从黑色遮罩里**挖出来**（画原始画面 + 虚线边框），其余区域保持暗——这才是 Snipaste 的手感。不要用实心色块覆盖 |
| 遮罩强度 | `Theme::kMask` alpha = 165。115（45%）在浅色桌面上几乎看不出压暗效果 |
| 悬停检测边框 | 一律 **1px 实线**（`Theme::kAccent`），和手动选区完全一致。不要用虚线——虚线和"检测中"的语义混在一起，Snipaste 也是实线 |
| 悬停检测（选区已定） | 只画实线轮廓，**不要**再叠主色填充：那会让整个选区发蓝，看起来像"截图直接蓝屏" |
| 截图光标 | 位图取自抓屏那一刻（`GetIconInfo`/`DrawIconEx`），**位置也固定在抓屏那一刻**（`m_snapshot.cursorPosition`）。`~` 的语义是"把截图时的光标画进画面"，不是跟随当前鼠标 |
| 整屏元素 | 桌面/根节点这类占满屏幕的元素**一律不显示**。UIA 链全整屏时退回顶层窗口矩形；窗口也整屏就不画框（否则选区外全亮 + 整屏虚线） |
| 默认层级 | 两种模式都从光标下**最深的块**开始（指哪块框哪块），滚轮往上回到容器/窗口 |
| 检测时机 | **只在 `Idle`（还没有选区）时检测**。用户一开始手动拖拽就 `clearDetection()`；选区一旦确定（`Adjusting`）彻底停止识别，避免高亮块干扰 |
| 自动选区 | 单击落下的自动选区必须**可拖动、可改大小、弹出工具栏**。锚点规则见下条 |
| 锚点显示条件 | 统一用**短边 >= `kAnchorMinSide`(48)** 判断。小元素（图标/小按钮）、整窗都只给方框；悬停预览同样遵循这一条，否则锚点比内容还大 |
| 选中手柄 | 单选时 8 个手柄统一为**灰白小方块**（`#E8E8E8` 填充 + `#505050` 描边），选中框用**淡灰点线**，不用主色蓝。旋转点是小圆点，**不画引线**。角手柄 + `Alt` 拖动 = 旋转。旋转后的手柄坐标由 `Annotation::handlePositions()` 统一套 `rotationTransform()`，`moveHandle()` 再反向映射回局部坐标 |
| 旋转支点 | `Annotation::rotationAnchor()` **永远返回当前 `rawBoundingRect().center()`**。不要做"首次旋转锁定"——先转、再缩放（中心变了）、再转时支点会停在旧位置，图形绕不存在的点转，看起来就是"锚点不是中心" |
| 异步任务后的工具栏 | `runOcr` 等会先 `m_paintBar->hide()`，完成后**必须** `restorePaintBarAfterAsync()` 恢复。以前成功路径忘了恢复，识别完工具栏就永久消失 |
| 手柄拖拽越界 | 「固定边」不是固定索引，要按**鼠标当前在矩形中心的哪一侧**动态决定：`dragsLeft = pos.x() < center.x()`，固定边取相对侧。若一直用旧 `right` 当固定边，拖过对边后宽度被压成 0（长条、另一侧锚点一路跑）。另外**不能**因为中间态宽/高为 0 就 `return`，否则卡在退化帧，之后的拖拽全部失效 |
| 文本 | 8 手柄：角/上下边 = 按比例改字号，左右边 = 只改宽度（自动换行）。字号范围 **6~400**。输入框与落定标注**必须同一字号**（`m_textBoxFontSize` 记录，滚轮可调），落定后把 `layoutWidth` 写回 `TextShape::setBoxWidth`，否则多行文本会重新按不换行排版 |
| 箭头 | 笔杆是**锥形**：起点极细（0.6px）→ 箭头端最粗。**末端半径必须等于箭头三角根部的半宽（`headLen * 0.42`）**，否则交界处会鼓包/台阶。双向箭头两端粗、中间细。用实心多边形拼，不要用可变宽 QPen，也**不要**在根部额外画圆补缝（那个圆比三角还宽，会鼓出一个包） |
| 铅笔/画笔 | 采样点用 **Catmull-Rom 转三次贝塞尔**（张力 1/6）连接，不要用"原始点当二次控制点"（拐弯处会尖角/锯齿）。采样阈值 0.6px，并做 0.7 权重的低通滤波抑制手抖 |
| 绘制裁剪 | 进行中形状的 `setClipRect` 要比选区**外扩 2px**，严格裁剪会切掉边缘的抗锯齿半透明像素，看起来就是毛刺 |
| 矩形/椭圆填充 | `ToolStyle::filled` 控制，右键工具栏对应按钮切换「空心 / 实心」。实心图形整块都可点中；**不要**新增独立工具按钮占工具栏 |
| 绘制光标 | 选中工具后整个画布统一 `Qt::CrossCursor`（含选区内部），只有锚点处保留缩放光标 |
| 放大镜标注 | `MagnifyShape` 完成后（`m_finished`）**只画放大画面**，不画目标框/源框/引导线——那些只是摆放时的辅助线。另外放好一个就要把工具复位成 `Tool::None`，否则点别处会开始画下一个 |
| 单击落选区 | `mousePress` 会 `clearDetection()` 停止识别，因此必须先把当次高亮目标存进 `m_clickTargetRect`。松手时读 `m_hoverWindow` 会拿到空值、退回 `bestWindowRectAt()`（最大化窗口＝整屏）—— 这就是"点元素却截整屏"的根因 |
| 元素块 | UIA 层级里 `hierarchy[0]` 是最深的块（按钮/输入框/列表项）。窗口模式默认取最外层，元素模式默认取最深层；滚轮改层级后，**单击落选区必须用当前高亮的这一层** |
| 放大镜 | 选区确定后仍然显示，取样点跟随当前鼠标（用于取色），但**不再画红色十字准心/中心像素框**——选区已定，用户是在看固定内容，红线只会挡视线。有工具激活或有标注被选中时整体隐藏（会挡住落笔点） |
| `` ` `` / `~` | 只切换**本次会话**的鼠标显示，不写回 `snip/capture_cursor`。写回会让"首选项关掉光标"被一次按键永久改掉 |
| 取色面板 | 与放大镜重叠时自动避让到放大镜下方/左侧 |
| 窗口矩形 | 必须用 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`。`GetWindowRect` 含 Win10/11 约 7~8px 的不可见缩放边框，直接用它选区四周永远差一圈 |
| 本进程窗口 | `WindowDetector::setOverlayWindow()` 登记遮罩 HWND，**只排除遮罩自己**。以前排除整个本进程，导致首选项/分组管理/白板无法被截图识别 |
| 选整窗 | 默认单击落在最具体的元素块上；窗口内按钮密集时很难点中整窗，提供 **Alt + 单击 = 直接选整窗**。整窗选区同样带 8 个锚点，可拖动调整 |
| 浮层文案编码 | 浮层里的按键/说明是 `const char*`，**必须 `QString::fromUtf8`**。用 `fromLatin1` 会把 UTF-8 中文拆成乱码；按键名尽量写纯 ASCII（`Alt+Click` 而不是 `Alt + 单击`） |
| OCR 精度 | 识别前把小图放大（短边 < 400px 时放大到约 800px，2~4 倍）。Windows OCR 对小于约 40px 高的文字识别率明显下降，这是"识别不准"的主因 |
| 快捷键浮层 | 左下角半透明黑底（alpha 150）帮助浮层，键帽白底黑字 + 中文说明。**鼠标移到浮层上才隐藏，移开立即恢复**；开始拉选区后永久隐藏。几何统一由 `shortcutTipsRect()` 计算（绘制与命中测试共用） |
| 元素徽标 | 左上角不显示元素类型徽标（`drawElementBadge` 已删除）。元素/窗口的区别只体现在边框是否带 8 个锚点 |
| 标注自动选中 | `annotate/auto_select_on_creation` 控制。新建形状后必须 `update()`，否则选中框要等下次鼠标移动才出现 |
| 光标截图 | 位图走 Win32 `GetIconInfo` + `DrawIconEx`（`QCursor::pixmap()` 在 Win11 上常返回空）。`GetCursorInfo` 的 `ptScreenPos` 是**物理像素**，而 `Snapshot::cursorPosition` 是逻辑坐标，必须除 dpr，否则高 DPI 下画到屏幕外 |
| 绘制性能 | 快照缩放只做一次（`m_snapshotLayer`），每帧 1:1 blit + 4 个 `fillRect` 画遮罩。**不要**每帧 `drawPixmap(rect(), snapshot)`（那是缩放绘制），也**不要**每帧新建整屏 pixmap |
| 窗口枚举 | `WindowDetector` 的顶层窗口列表缓存 200ms。每帧 `EnumWindows` + `OpenProcess` 是卡顿主因 |
| 贴图比例角标 | 缩放中（拖角/滚轮）常显，松手后 1s 隐藏；锚在**图片矩形**左上角，不是窗口内容区（内容区含 8px 阴影边距）；小图时角标按图片尺寸收缩，不能算出负宽度被丢弃 |

3. ✅ **启动冒烟**：exe 能起来，进程存活 3 秒不崩（`tasklist` / 退出码验证）
4. ✅ **日志无 ERROR**：读 `%LOCALAPPDATA%/F-Capture/log/fcapture.log`
5. ✅ **对照验收清单逐条自查**：能自动化的跑，不能自动化的标注「需人工确认」
6. ✅ **保持程序运行，交给用户截图验证**
   - 冒烟通过后**不要关闭进程**

   - 报告里写「程序已启动，可以直接截图验证」

**不允许**把编译不过、启动崩溃、或明显未完成的东西交给用户。

### 7.1 首选项 / 分组管理改动必须额外检查

- **图标正常**：`ElaAwesome.ttf` 从 DLL 内嵌加载。图标全变方框 = `eApp->init()` 漏了或调用顺序错。
  高 DPI 下发糊说明用的是 `QIcon` 位图路径，改成 `ElaIcon::getElaIcon()` 或按字体自绘。
- **主题切换**：Dark ↔ Light 不残留硬编码颜色。
- **配置读写回归**：`PreferenceDialog` 内所有项仍能正常读写 `config.ini`。
- **列表 / 缩略图**：`ElaListView` 在 `IconMode` 下不画模型里的缩略图，贴图列表、历史列表这类
  带图片的列表要自绘 `paintEvent`，不要指望 `QStandardItem(QIcon, text)` 能显示出来。
- **带图标按钮**：`ElaPushButton` 的 `minimumSizeHint` 不含图标宽度，短标签（"新建"/"删除"）
  会裁掉图标。统一用 `iconButton()` 显式按「图标 + 间距 + 文字 + 内边距」设 `setMinimumWidth`。
- **只读列表要可操作**：历史缩略图单击 = `PinManager::pasteImage()` 贴到屏幕，
  右键 = 保存图片 / 从历史删除。**不要自己再造一个预览窗口**——贴图窗口本来就支持缩放、旋转、置顶。
- **不要用 GetWindowRect 当可见边界**：DWM 有约 8px 不可见缩放边框。
- **自绘列表/网格不要用 `WA_TranslucentBackground`**：命中不到背景时旧像素不会被清除，拖动分隔条/滚动会叠加出重影。`paintEvent` 必须先用对话框底色 `fillRect(rect(), ...)` 清屏。
- **带图标按钮**：`ElaPushButton` 的 `minimumSizeHint` 不含图标宽度，`"复制"`/`"重新识别"` 这类短标签会把图标裁掉，必须显式 `setMinimumWidth(文字宽 + 64)`。
- **关于页放 logo**：用 `:/icon.png`（同一份 1254px 源图），按 `64 × dpr` 平滑缩放后 `setDevicePixelRatio`，别直接 `setScaledContents` 拉大。
- **弹窗标题栏**：`ElaDialog` 的关闭/最小化按钮尺寸跟 `AppBarHeight` 绑定，
  默认 40px 在高 DPI 下偏小，首选项/分组管理统一 `setAppBarHeight(52)`。
- **保存目录必须有默认值**：`ConfigManager::defaultSaveFolder()` 返回系统图片目录。
  自动保存目录为空时回落到它（否则"开了自动保存却什么都不发生"），
  快速保存回落到 `<图片目录>/Snipaste`，首选项输入框直接显示该默认值而不是空框，
  「浏览…」也以它为起始目录。
- **输入类控件必须按主题重设调色板**：`ElaSpinBox` / `ElaLineEdit` / `ElaComboBox`
  会给内部 `QLineEdit` 单独设调色板，切到 Light 后不会自动跟随，
  表现为**浅色下输入框文字仍是白色（白底白字）**。
  `PreferenceDialog` 用 `themeInputs(page)` 在构建时和 `themeChanged` 时统一刷一遍，
  递归处理内部 `QLineEdit`。新增输入控件不需要单独接线。

### 7.2 `Q_OBJECT` 的放置规则

- `Q_OBJECT` 类必须有对应的 `.h`，或者放在 `.cpp` 里**并手动 `#include "<file>.moc"`**
  （`ElementDetector.cpp` / `GroupManagerDialog.cpp` 末尾就是这么做的）。
- **匿名命名空间里不能放 `Q_OBJECT`**：AUTOMOC 找不到它，构建会直接失败在 `cmake_autogen`。
  这类内部控件改用 `std::function` 回调，不要为它造信号。

### 7.3 托盘菜单边界

托盘只放高频操作：截图 / 贴图 / 消隐贴图 / 分组管理 / 白板 / 首选项 / 重启 / 退出。
**导出诊断信息**在首选项的「关于」页，「取消（中止截图）」只存在于截图过程中，都不进托盘。
